# AGENTS.md — SDN DDoS Real-time Dashboard

## 1. Project Overview

This project builds a real-time web dashboard for an AI-based DDoS detection and mitigation system in a Software Defined Network (SDN).

The SDN environment runs on Ubuntu VMware and uses Mininet, Ryu Controller, and OpenFlow.

The AI detection and mitigation system is being developed and validated separately in ChatGPT Work/Astra.

The dashboard will be developed with Codex.

## 2. Technology Stack

Frontend:
- React
- TypeScript
- Vite
- Recharts for traffic visualizations
- React Flow for interactive SDN topology

Backend:
- Python
- FastAPI
- WebSocket
- REST API

SDN and AI:
- Mininet
- Ryu Controller
- OpenFlow
- Existing AI inference pipeline

The actual AI model architecture, parameters, and interfaces must be read from the handoff documentation. Do not assume values.

## 3. Core Requirements

The dashboard must display actual data generated by the running AI–SDN system.

Required modules:

1. Network Overview — real-time traffic statistics.
2. AI Detection — prediction results and confidence.
3. Attack Alerts — detected and confirmed DDoS events.
4. Mitigation — DROP rule status and blocked sources.
5. SDN Topology — hosts, switches, and links.
6. Attack History — historical detection and mitigation events.
7. Performance — measured detection and mitigation latency.

## 4. Real-time Communication

Use WebSocket for live events and REST API for initial snapshots, historical data, and state reconciliation.

Handle:
- Connection and reconnection.
- Event identifiers and timestamps.
- Duplicate and missing events.
- Consistent frontend/backend state.
- Flow rule installation, verification, and expiration.
- Clear connection and data freshness indicators.

Do not fabricate successful mitigation results.

A mitigation must not be displayed as VERIFIED until the system has supporting evidence from the SDN controller or switch.

## 5. Project Architecture

- frontend/: React + TypeScript dashboard.
- backend/: FastAPI and WebSocket services.
- docs/: architecture, AI handoff, and API contracts.
- tests/: automated and integration tests.

## 6. Development Rules

- Do not modify the existing AI model or SDN mitigation logic without explicit approval.
- Read project documentation before implementing integrations.
- Use actual backend data contracts.
- Keep mock data separate and clearly labeled.
- Prioritize correctness, maintainability, security, and performance.
- Avoid blocking the Ryu monitoring and mitigation loops.
- Use asynchronous and bounded event delivery where appropriate.
- Never commit credentials, tokens, or secrets.
- Add tests for important functionality.
- Do not claim that a feature has been tested unless tests have actually been run.
- Explain planned architectural changes before significant modifications.

## 7. Development Workflow

Phase 1: Review repository and define architecture.

Phase 2: Implement dashboard layout and reusable components.

Phase 3: Implement FastAPI REST and WebSocket infrastructure.

Phase 4: Integrate actual AI and Ryu events.

Phase 5: Verify end-to-end real-time behavior.

Phase 6: Optimize dashboard usability and performance.

## 8. Communication

Respond to the user in Vietnamese.

Explain important commands and changes step by step.

Before making major architectural changes, present the plan and obtain approval.

The primary goal is a functional, accurate, professional real-time SDN–AI DDoS monitoring and mitigation dashboard, not a static demonstration.
